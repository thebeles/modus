# REST API

Префикс /api/v1. [Swagger локального запуска](http://localhost:4000/api/v1/docs), [OpenAPI JSON](http://localhost:4000/api/v1/openapi.json). Swagger доступен в режиме разработки. Для запроса через Swagger сначала откройте интерфейс и войдите, затем передайте Origin и CSRF в клиенте, который может их установить.

JSON-ответы используют `{ data, requestId }` и `{ error: { code, message, details }, requestId }`. CSV и загрузки возвращают содержимое с Content-Disposition. Невидимые записи дают 404. 409 обозначает конфликт версии, недопустимый переход или конфликт данных.

| Ресурс | Основные операции |
|---|---|
| /auth | login, demo, me, refresh, logout, change-password |
| /appeals и /work-queue | поиск и фильтры, карточка, изменение, переходы, назначения, диалог, события |
| /problems и /object-links | наблюдения, источники, переходы, предложения и решения о связях |
| /improvements | управление стадиями, задачи, согласование, измерения, верификация, приглашения |
| /radar и /analytics | агрегаты, внимание, процессы, темы, результаты, ограниченный CSV |
| /publications | библиотека, черновики, согласование, выпуск и отзыв |
| /admin | структура, доступ, классификаторы, маршрутизация, сроки, аудит и сбои доставки |
| /notifications и /notification-preferences | список, прочтение, настройка подтверждения регистрации |
| /attachments | multipart upload и проверяемое скачивание |
| /ai | возможности, четыре вида подсказок |

POST /appeals принимает `Idempotency-Key` и объект с полями `type`, `description`, необязательными `title`, `categoryId`, `processId`, `proposedSolution`, `attachmentIds` и `visibility`. Повтор с тем же телом возвращает прежний ID. Новое тело с уже использованным ключом возвращает 409.

Например, POST /appeals/:id/transition принимает `{ "expectedVersion": 1, "action": "REVIEW" }`. Доступные действия вычисляет сервер. Изменяющие запросы с сессией требуют заголовка `X-CSRF-Token` со значением cookie `modus_csrf` и совпадения Origin. Страницы списков используют `page` и `limit` с максимумом 100. Экспорт ограничен 1000 строками.

`POST /appeals/:id/reroute` принимает версию, обоснование `text` и необязательные `categoryId` и `processId`. При утрате доступа после перевода возвращает `readable: false`. `controlDueAt` — ближайший контролируемый срок, `lastMeaningfulActionAt` — дата последнего содержательного действия.

Измерения и верификация принимают `evidenceIds` из загрузок текущего пользователя, измерения также принимают `sourceType`. Для правок публикации доступны `PATCH /publications/:id` и `POST /publications/:id/request-changes`. Оба требуют текущей версии.

`GET /admin/worker-status` возвращает сводку worker и outbox. `POST /admin/outbox-failures/:id/retry` доступен администратору и сохраняет исходный ключ дедупликации.

Очередь поддерживает `assigneeId` и полуоткрытый интервал `dueFrom ≤ controlDueAt < dueTo` в UTC. Справочник доступных исполнителей выдаёт `GET /work-queue/assignees`. В карточке `timing` содержит активное время и время ожидания в секундах, а также до 30 последних периодов. Это календарная длительность состояний. Рабочий календарь применяется отдельно к срокам SLA.

`GET /analytics/appeals` возвращает объём и распределения, `GET /analytics/sla` — сроки и первый ответ, `GET /analytics/improvement-outcomes` — агрегаты и пагинированные внедрённые улучшения. Фильтр `outcome` меняет только детализацию. `GET /radar/recurrences` возвращает подтверждённые и предложенные связи, если хотя бы одно обращение попадает в когорту, а оба доступны пользователю. Кандидат на повтор требует проверки человеком.

`GET /publications/:id/revisions` доступен редакционным ролям в области улучшения. Для исторических публикаций создаётся исходный снимок имеющейся редакции. План проверки поддерживает `minimumSampleSize`, `requireSameSource` и `maxPeriodDifferencePercent`. Разница длительности измеряется относительно периода до внедрения.

## Анонимные обращения

Публичные операции требуют заголовок Origin, соответствующий WEB_ORIGIN. Для чтения, ответа и скачивания передавайте токен в заголовке X-Appeal-Token. Храните токен у автора. API выдаёт его при регистрации обращения и сохраняет только SHA-256.

| Метод и путь | Вход и результат |
|---|---|
| POST /anonymous/appeals | title, type, text и необязательный attachment. Возвращает number и token |
| POST /anonymous/track | Пустой JSON-объект или cursor. Возвращает статус, тип решения, страницу переписки и nextCursor |
| POST /anonymous/reply | text и необязательный attachment. Ответ в период ожидания возобновляет рассмотрение |
| POST /anonymous/attachments/:item | Возвращает attachment по идентификатору сообщения и токену обращения |
| GET /appeals/:id/anonymous-thread | Страница переписки для допущенного обработчика спецочереди. Принимает cursor |
| GET /appeals/:id/anonymous-thread/attachments/:item | Возвращает attachment для допущенного обработчика |

Вложения передаются как текст UTF-8 до 64 КиБ. Сведения о файле и его исходное имя не передаются. Для ответов обработчик использует обычные действия COMMENT, CLARIFICATION и RESOLVE в карточке. Публичная переписка, решение и вложения хранятся в шифрованном виде. В карточке обращения заголовок и статус доступны спецочереди. Личные данные следует исключить и из заголовка, и из текста.

## Предложения сотрудников

Доска и голоса доступны внутри подразделения с учётом демонстрационного режима учётной записи.

| Метод и путь | Назначение |
|---|---|
| GET, POST /proposals | Список с sort=popular или sort=recent. Создание принимает title, description |
| PUT, DELETE /proposals/:id/vote | Добавление или снятие голоса пользователя. Повтор безопасен |
| GET, POST /proposals/:id/comments | Страницы обсуждения и добавление комментария с полем body |
| POST /proposals/:id/convert | Владелец улучшений вводит goal и scope. Возвращается id черновика обычной инициативы |

## Клиентские отзывы

Сотрудники обработки читают отзывы своего подразделения. Импорт и изменение связей требуют PROBLEM_OWNER. Цели проверяются по действующим правам доступа, подразделению и типу данных.

| Метод и путь | Назначение |
|---|---|
| POST /customer-reviews/import | Поле csv с текстом CSV в UTF-8. Колонки date, title, body. Дата в формате YYYY-MM-DD, до 500 строк и 64 КБ |
| GET /customer-reviews | Страницы, распределение по категориям и фильтры category, appealId или improvementId |
| GET /customer-reviews/targets | Поиск допустимых целей по q и target=appeal или target=improvement |
| GET /customer-reviews/:id/similar | Ранжированные кандидаты по триграммному сходству текста |
| POST, DELETE /customer-reviews/:id/links | Добавление или удаление связи. Вход target и targetId |

Категории вычисляются по текстовым правилам. Импорт проверяет весь файл до записи. Дедупликация использует дату, нормализованный заголовок и текст в рамках подразделения. Близкие отзывы с разных дат сохраняются как отдельные сигналы.

## Расширенный анализ обращений

POST /ai/appeal-triage принимает id и consent=true. Доступен допущенному обработчику обычного внутреннего обращения. Groq предлагает категорию, группы похожих обращений с типом сходства, гипотезы причин, действия и KPI. Сервер проверяет, что идентификаторы категории и участников групп были переданы провайдеру. Принятие и отклонение рекомендации регистрирует POST /ai/usage/:id/decision. Подтверждённые пользователем группы можно сохранить как карточку проблемы с relatedAppealIds через POST /problems. Изменение категории и сохранение KPI используют обычные API карточки и плана измерений.

## Интеграция с 1С

| Метод и путь | Назначение |
|---|---|
| GET /one-c/capabilities | Доступный режим http, simulator или null |
| GET /one-c/products | Товары и остатки |
| GET, POST /one-c/requests | Свои заявки или создание по sku, quantity и необязательному improvementId. POST требует Idempotency-Key |
| POST /one-c/requests/:id/refresh | Обновление статуса или повтор незавершённой отправки с прежним ключом |
| GET /one-c/improvements/:id/requests | Заявки для пользователей с доступом к инициативе |
| GET /one-c/journal | Журнал собственных операций |

HTTP-режим требует права ONEC_OPERATOR и опубликованного в конфигурации 1С HTTP-сервиса. ONEC_API_URL указывает базовый URL этого сервиса. Адаптер передаёт Authorization: Bearer и ожидает JSON напрямую без оболочки Modus.

| Запрос адаптера | Контракт |
|---|---|
| GET products | Массив объектов с полями sku, name, stock. stock — целое неотрицательное число |
| POST requests | Вход requestId, sku, quantity. Выход externalId и status. Заголовок Idempotency-Key равен requestId |
| GET requests/{externalId} | Ответ с теми же полями externalId и status |

Допустимые статусы SUBMITTED, PROCESSING, COMPLETED и REJECTED. Сервис 1С должен атомарно сохранять ключ идемпотентности вместе с заявкой и возвращать ту же заявку на повторный POST с тем же ключом. Это покрывает обрыв связи после создания заявки на стороне 1С. externalId должен быть стабилен в пределах одного опубликованного сервиса.
