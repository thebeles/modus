# Безопасность

## Модель угроз

Автор пытается открыть чужую карточку или файл по ID. Обработчик пытается пересечь границу очереди. Руководитель получает объект за пределами рабочей области. Администратор использует системную настройку для чтения частных данных. Дополнительные каналы раскрытия включают поиск, аналитику, экспорт, связи, уведомления, публикации и внешние подсказки.

## Контроли

- Общая серверная политика фильтрует выборки до получения результата. Карточка, вложения, связанные источники и подсказки проходят объектную проверку.
- Сессии представлены случайными токенами с хешами в базе. Cookie сессии имеет HttpOnly, SameSite=Strict и Secure в production. Проверяются Origin и CSRF. Ротация удаляет старую сессию, смена пароля отзывает все сессии пользователя.
- Zod-валидация запрещает дополнительные поля. Мутации проверяют версии и переходы. Prisma параметризует запросы. Поиск ограничен длиной строки и размером страницы.
- Вложения проверяются по типу и сигнатуре, лежат вне веб-каталога, выдаются как скачивание через API. Имена очищаются. В production доставка PDF закрыта.
- UI выводит текст без интерпретации HTML. CSV включает ограниченные поля без произвольного текста. Публикация хранит редакционное содержание в отдельной записи.
- Логи API содержат идентификатор запроса и класс непредвиденной ошибки. Аудит доступен администратору в сокращённом виде. Содержательные события доступны через карточку в рамках её политики.
- У Groq нет прав на изменение доменных записей. Внешний запрос выполняется по согласию и только с допустимым контекстом.

Промышленное развёртывание требует отдельной роли PostgreSQL с ограниченными DDL-правами, TLS, проверки секретов, доступа администраторов и сроков хранения, а также проверки резервного восстановления.
