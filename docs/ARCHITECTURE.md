# Архитектура

React, TypeScript и Vite обслуживают рабочее пространство. TanStack Query получает серверное состояние, React Hook Form и Zod проверяют ввод. Приложение использует React Router, Radix, Tailwind, Lucide и Recharts. В режиме разработки прокси Vite передаёт /api в NestJS. В Compose этим занимается Nginx.

NestJS разделён по областям. `Appeals` управляет обращениями, `Cases` ведёт проблемы и улучшения, `Radar` фильтрует агрегаты и связи, `Publications` ведёт редакционный выпуск. `Policy` формирует объектные ограничения. `Routing` выбирает маршрут. `Files` использует интерфейс хранилища, текущая реализация работает с закрытым локальным каталогом.

PostgreSQL хранит доменные записи, сессии, ключи повторной отправки, историю и outbox. Worker доставляет уведомления и контролирует сроки. История, изменение доменного состояния и постановка уведомлений записываются в одной транзакции. Критические изменения используют оптимистическую версию. Повтор одного запроса создания обращения синхронизируется блокировкой PostgreSQL и ограничением уникальности.

Границы интеграций: корпоративный identity provider может выдавать серверную сессию через новый адаптер входа. События outbox можно передавать дополнительному транспорту. Для 1С и Битрикс24 следует согласовать идентификаторы, разрешённые поля и источники статусов, затем добавить отдельный адаптер с дедупликацией и аудитом. Файлы можно перенести в S3-совместимое хранилище через интерфейс `FileStorage`.
