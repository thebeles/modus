# Демонстрация «Модус · Контур»

## Подготовка стенда

Из корня репозитория с Docker Compose 2.24.4 или новее выполните:

```powershell
$demo = @('-p', 'modus-hackathon', '-f', 'backend/deploy/docker-compose.yml', '-f', 'backend/deploy/docker-compose.hackathon.yml')
docker compose @demo up --build -d --wait
docker compose @demo ps -a
curl.exe -fsS http://localhost:55531/api/v1/health/ready
```

Web и API через Nginx доступны на [localhost:55531](http://localhost:55531), PostgreSQL для локальных проверок — на `127.0.0.1:55532`. Проект Compose создаёт отдельные тома БД и вложений. `migrate` должен завершиться с кодом 0. Worker работает отдельным контейнером. В стенде включён демовход и отключён Groq. Если на этих портах уже работает конкурсный стенд, используйте его имя проекта из `docker compose ls` для перезапуска.

| Кнопка демовхода | Адрес для ручного входа |
|---|---|
| Сотрудник | `employee@demo.local` |
| Обработчик | `handler@demo.local` |
| Руководитель | `manager@demo.local` |
| Администратор | `admin@demo.local` |

Пароль свежих локальных демоаккаунтов — `Modus-Demo-2026!`. Подготовьте отдельное окно браузера или профиль на каждую роль. При использовании одного окна выходите из сессии перед сменой роли.

## Показ за три минуты

1. **Сотрудник, 45 секунд.** Нажмите «Сообщить о проблеме», опишите неполную заявку на закупку, выберите категорию «Межотдельное взаимодействие» и отправьте. Скопируйте присвоенный номер.
2. **Обработчик, 45 секунд.** Найдите номер в очереди. Покажите назначение, срок и историю. Нажмите «Взять на рассмотрение», затем «В работу». Откройте «Запросить уточнение» и спросите, каких полей не хватает.
3. **Руководитель, 60 секунд.** Откройте Радар, выберите демонстрационные карточки и синтетические доказательства. Покажите повторяющиеся сигналы и переход в очередь. В улучшениях откройте `DEMO-I-01`. На вкладке «Результат» покажите значения до и после, фактическую дельту, целевой порог и вывод проверяющего.
4. **Сотрудник, 30 секунд.** В библиотеке откройте «Новый шаблон заявки на закупку». Завершите показ тем, что сотрудник получает понятный результат, а руководитель видит, что именно подтверждают измерения. Уточните, что все измерения синтетические.

## Показ за семь минут

1. Выполните подачу, найдите запись в очереди, возьмите на рассмотрение и переведите в работу. Добавьте служебную заметку, дождитесь подтверждения сохранения и запросите уточнение. В сессии сотрудника откройте уведомление, ответьте и покажите внешний диалог.
2. В Радаре откройте «Темы», покажите A-001 и A-015. Связь — проверяемая гипотеза о сходстве. Откройте `DEMO-I-01`, покажите владельца, источники, задачи и сведения о внедрении. Если хотите создать новый черновик, начните из A-001 как обработчик и заполните основание и цель. Для короткого показа пройдите дальнейшие этапы на подготовленной инициативе.
3. На «Результате» сравните `DEMO-I-01` и `DEMO-I-02`. Второй пример показывает недостаточность данных. Объясните роль независимого проверяющего и пределы выводов из демонстрационной выборки.
4. Вернитесь в сессию сотрудника, откройте подготовленную публикацию и приглашение к обратной связи. Для вопросов жюри откройте предпросмотр маршрутизации в администрировании и покажите резервный путь.

Полный путь создания инициативы, согласования, внедрения и проверки описан в [расширенном сценарии](../backend/docs/DEMO_SCRIPT.md). `DEMO-I-01`, `DEMO-I-02`, публикация и приглашения входят в штатный seed.

## Восстановление показа

- **Нет интернета.** Заранее соберите и запустите стек. Если контейнеры нужно запустить повторно, используйте `docker compose @demo up --no-build --pull never -d --wait`. При отсутствии локальных образов первая подготовка потребует доступ к Docker Registry и npm.
- **Недоступен Groq.** Продолжайте ручную подачу и Радар. У конкурсного стенда Groq выключен конфигурацией.
- **API или worker остановились.** Выполните `docker compose @demo restart api worker`, дождитесь успешной готовности API и повторите действие в UI. Для диагностики используйте `docker compose @demo logs --tail 50 api worker`.
- **Истекла сессия.** Войдите кнопкой соответствующей демороли. Повторное открытие карточки по номеру покажет сохранённое состояние.
- **Нужен новый исходный набор.** Выполните `docker compose @demo down` без `-v`. Замените имя проекта в `$demo` на свободное имя, например `modus-hackathon-clean`, затем выполните `docker compose @demo up --no-build --pull never -d --wait`. Прежние тома останутся доступны под прежним именем проекта. Только один из этих проектов может использовать фиксированные порты одновременно.
- **Нужна именно предыдущая сессия.** Верните прежнее имя проекта и запустите его с теми же параметрами после остановки нового проекта без `-v`. [Порядок резервирования PostgreSQL и вложений](../backend/docs/OPERATIONS.md).
