| В закупочной заявке могут отсутствовать назначение и параметры | [Датасет, A-001](../../backend/docs/reference/dataset.md) | Синтетический пример | «В учебном примере». Утверждать частоту таких случаев у заказчика нельзя. |
| Регистрация сохраняет обращение при недоступном маршруте | [D01](../FINAL_ACCEPTANCE.md) | Интеграция и E2E | «В конкурсной сборке запись сохраняется и ожидает назначения». |
| Обработчик видит следующий шаг, а автор может ответить на уточнение | [Репетиция](FINAL_REHEARSAL_REPORT.md) | Повторено через UI | Назвать роли и показать историю. |
| Приватные обращения и заметки ограничены объектными правами | [Приёмка безопасности](../RELEASE_READINESS.md) | Локальные тесты сервера и браузера | Говорить о проверенном разграничении. Общую гарантию безопасности не заявлять. |
| Радар подсвечивает сроки и потенциально связанные сигналы | [F-14, F-19–20](../FINAL_ACCEPTANCE.md) | Проверенные экраны, API и тесты | «Сходство — повод для проверки. Причину исследует человек». |
| Наблюдения и синтетические события в аналитике различаются | [D03, D08](../FINAL_ACCEPTANCE.md) | Проверки KPI, очереди и CSV | Сказать, какие фильтры выбраны. Правила малых групп для пилота открыты. |
| Один сигнал может стать источником инициативы, у инициативы может быть несколько источников | [E2E-05](../../frontend/tests/modus.spec.ts) | Браузерный сценарий | «Создаём инициативу, когда требуется изменение процесса». |
| Цель и направление изменения проверяются отдельно | [D06](../FINAL_ACCEPTANCE.md) | Доменная проверка, E2E | Пример 20 → 24 при цели ≤25 показывает ухудшение при формальном достижении цели. |

| Независимая проверка и редакционная публикация входят в цикл | [F-17 и F-21](../FINAL_ACCEPTANCE.md) | Интеграция и E2E | «В демо проверяет отдельная роль. Автор видит согласованный итог». |
