# Резервный план показа

Локально откройте [PDF](PITCH_DECK.pdf) и папку [снимков](screenshots). В резерве слайд 4 показывает форму и очередь, 5 — Радар, 7 и 11 — результат, 12 — недостаток данных, 10 — публикацию. Если экран не загружается около 10 секунд, продолжайте на соответствующем слайде. Скажите: «Покажу сохранённый экран конкурсной сборки».

| Сбой | Действие оператора |
|---|---|
| Нет интернета | Заранее собранные образы и локальный стенд. Для повторного запуска используйте `up --no-build --pull never -d --wait` из runbook |
| Groq недоступен | Продолжить ручную подачу. На конкурсном профиле Groq отключён |
| API отвечает ошибкой | Проверить `/api/v1/health/ready`. На демостенде выполнить `restart api` и повторить чтение карточки. На сцене сразу открыть PDF |
| Worker задержал уведомление | Автор открывает карточку через «Мои обращения». После показа проверить логи и `restart worker` |
| Сессия истекла или открыта другая роль | Переключиться в заранее подписанный браузерный профиль. Повторно войти демокнопкой при необходимости |
| Загрузка медленная | Открыть заранее загруженную карточку или снимок. Перед повторной отправкой проверить появление номера в «Моих обращениях» |
| Неожиданный статус | Объяснить, какой шаг уже выполнен. Использовать подготовленную карточку или создать новое обращение |
| Нет DEMO-I-01 | Слайды 7 и 11. Вне выступления поднять отдельный Compose-проект со свежим синтетическим томом по runbook |
| Порт занят | Проверить `docker compose ls`. Использовать активный проверенный стенд. Освобождать порт только остановкой известного демонстрационного проекта |
| Docker недоступен на площадке | Показать PDF и реальные снимки в том же порядке. Сохранить роли и переходы в речи |

Существующие данные и тома сохраняются. Подробные команды в [runbook](../DEMO_RUNBOOK.md).

[Резервный ролик](DEMO_VERIFICATION.webm) записан в браузере на конкурсной сборке. Он показывает переход от Радара к DEMO-I-01 и затем к DEMO-I-02. Длительность 18,6 секунды. Ролик без звука, спикер комментирует увиденное.
